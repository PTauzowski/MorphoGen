Two results are worth stating plainly.

**`Vibrations` fails all six.** Not a regression in these examples — it is the consequence of
`LinearElasticityWeighted` being folded into `LinearElasticity` in `334fa7f` without migrating
callers. All six fixtures reference the removed class, as do 51 files in total. Vibrations'
*own* examples (`examples/Pillar/quickTest.m`) pass; these shared ones do not. Any Vibrations
baseline has to be taken on its native examples, which is why the merge acceptance test is the
**union** of what each branch passes, not the intersection.

**`develop` now passes more of these than either feature branch.** After the Phase 1 repair it
is the only branch that runs `LameProblemTest`. That inverts the situation the survey started
from and means develop, not CAS_Arm, is the better base for the merged tree.

The single failure is `equivalentPlasticStrainIsScalarNotBroadcast` — the scalar accumulated
equivalent plastic strain being broadcast into the 3-component `pstrain` slot. That is a
state-variable design question rather than an error (Box 9.4 keeps the plastic strain tensor and
ε̄p as distinct variables), so it is recorded under Rule 2 rather than fixed during the merge.

## Not yet captured — numerical references

This baseline records **what runs**, not **what the numbers are**. A silently wrong stiffness
matrix still converges to something plausible and would pass every row above. The numerical
oracle described in Phase 0 — final compliance, volume fraction and iteration count for
`Cantilever.m`, `Beam99.m` and `Lshape.m` on `main` — is still outstanding, and gates Phase 5
rather than Phase 1.

Note that `main` needs its one-line `plotSupport` fix applied in the worktree before it will
run; that fix is already present on develop and must not be committed to `main`, which is
read-only.
